# Incident calibration corpus

Version 1 is an offline, registry-history-only corpus. `cases.json` is checked-in hand-authored calibration data: each case contains expected events independently read from its raw packument/API response; it is not generated by the analyzer. Each case is an observation about one pinned raw response, not a claim that the package was compromised. Labels are single AI-assisted labels and are **not independently validated**. Missing or removed versions are recorded as `insufficient_evidence` or `unknown`.

Splits are frozen before evaluation. `split` is assigned by SHA-256 of `id`: the first byte modulo 10 gives development (0–5), validation (6–7), or holdout (8–9). The checked-in split is authoritative and tests reject drift. Holdout metrics are never printed without `--final`; a final run writes `calibration/incidents/results/final-holdout.json` and a second final run refuses to overwrite it.

`observations` are registry observations only. `conclusion` is separate and may be uncertain. `sources` are package/advisory URLs known to exist; a case with a non-certain historical claim uses an uncertainty conclusion and explains the limitation in `notes`. No reviewer is asserted or filled in.

The raw files are the only registry evidence. The evaluator uses the production parsers and event/correlation functions offline. Methodology remains 0.4 and no shipped policy is enabled.
